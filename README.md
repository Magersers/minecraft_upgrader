# Minecraft Upgrader — 0.1.1-alpha

Мод с рулеткой улучшения предметов для **Minecraft Java 1.20.1**, **Forge 47.4.10**, **Java 17**. Результат апгрейда и списание предметов рассчитывает сервер.

Это исходники восстановленной сборки от 25 сентября 2026 года. Сборка прошла успешно, проверка ядра экономики выполнила 10 018 утверждений. Запуск в Minecraft и совместимость с конкретными сборками пока не проверены.

## Установка и запуск

1. Установите Minecraft 1.20.1 с Forge 47.4.10.
2. Положите собранный `upgrade-0.1.1-alpha.jar` в папку `mods` нужного игрового профиля. Удалите старую версию мода.
3. Для сетевой игры установите мод на сервер и на клиент каждого игрока.
4. В режиме выживания возьмите предмет для улучшения в основную руку.
5. Нажмите **T**, введите **`/upgrade`** и нажмите Enter.
6. Выберите количество предметов ставки и более дорогую цель в окне рулетки.

Отдельная горячая клавиша пока не назначена. Неудачный апгрейд расходует ставку без выдачи целевого предмета.

## Сборка из исходников

Нужен JDK 17 и доступ к серверам зависимостей Gradle, Forge и Minecraft. Gradle Wrapper включён в репозиторий.

Linux / macOS:

```sh
./gradlew build
```

Windows PowerShell:

```powershell
.\gradlew.bat build
```

Результат: `build/libs/upgrade-0.1.1-alpha.jar`. Задача `build` включает `coreTest` и преобразование имён классов для запуска в Forge.

Только проверки ядра экономики:

```sh
./gradlew coreTest
```

## Шансы

```text
стоимость ставки = цена одного исходного предмета × количество
шанс = min(0.95, 0.85 × стоимость ставки / цена цели)
```

Цена цели должна превышать стоимость ставки. Например, ставка стоимостью 100 на предмет стоимостью 200 даёт **42.5%**. Коэффициент `0.85` находится в `CostEngine.DEFAULT_EFFICIENCY`; это не фиксированный шанс 85% для каждого апгрейда.

## Оценка предметов

Базовые оценки задаются профилями `data/<namespace>/upgrade_values/*.json`. Начальный профиль: `src/main/resources/data/upgrade/upgrade_values/baseline.json`.

Ядро выбирает самый дешёвый известный путь получения предмета. Для рецепта складываются стоимости ингредиентов и накладные затраты, затем сумма делится на количество результата. Из альтернатив ингредиента выбирается самая дешёвая, но для расчёта должны быть известны цены всех альтернатив. Нестабильные циклы и зависящие от них предметы исключаются из оценки.

Автоматически читаются обычные shaped/shapeless-рецепты, камнерез и стандартные типы приготовления, в том числе с модовыми предметами. Для нестандартных машин и механик нужны явно заданные `routes` или отдельные адаптеры.

Профиль добычи с моба (`encounter`) рассчитывает ожидаемые затраты:

```text
(поиск + бой + расходники + вероятность смерти × потери + обустройство / горизонт)
/ (вероятность победы × вероятность дропа × среднее количество)
```

Эти параметры задаются автором профиля; текущая версия не определяет автоматически сложность всех модовых мобов и их таблицы добычи. Все затраты должны быть откалиброваны в общей системе единиц для конкретной сборки.

Поля `confidence` задают доверие к оценке, `gates` — необходимые достижения, `deny` — запрет предметов. Для апгрейда требуется доверие не ниже `0.85`. Профили перечитываются при запуске сервера и глобальной перезагрузке datapack.

## Ограничения alpha

- Начальные цены демонстрационные и требуют настройки под сборку.
- Полное покрытие всех модовых предметов, специальных рецептов и дропа ещё не реализовано.
- Предметы с NBT, повреждениями, инвентарём, жидкостью или энергией и яйца призыва исключаются.
- Журнал транзакций, устойчивый к аварийному завершению сервера, пока отсутствует.
- Сборка и тесты ядра не заменяют испытания в игре.

## Структура

- `Upgrade.java` — регистрация мода, команды и событий.
- `Economy.java` — профили, импорт рецептов и доступность предметов.
- `Network.java` — сетевые сообщения и серверная обработка апгрейда.
- `client/UpgradeScreen.java` — интерфейс рулетки.
- `core/CostEngine.java` — расчёт стоимости и вероятностей.
- `src/test/` — проверки ядра.

`META-INF/source-recovery.zip` — резервная копия исходников восстановленной сборки, включённая в JAR. При дальнейшей разработке актуальные исходники находятся в дереве Git, а не в этом архиве. `RESTORED_BUILD.md` описывает происхождение сборки. `LICENSE.txt` и `CREDITS.txt` сохранены из Forge MDK и содержат сведения о Forge.
